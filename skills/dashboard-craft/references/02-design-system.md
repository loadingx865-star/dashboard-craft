# 阶段 1 —— 设计单一真源

## 目的

让"颜色、字号、间距、圆角、阴影、图表配色"有唯一权威来源，任何人（包括 AI）都不能凭感觉临时决定。这是解决"前后两期风格不一致"的根本手段。

## 三种做法，按可靠性排序

| 做法 | 可靠性 | 适用 |
|---|---|---|
| 只有设计稿（Figma） | 低 | 人会看走眼，AI 读不到 |
| 设计稿 + 文档描述 | 中 | 描述容易模糊，AI 会自由发挥 |
| **可机读 token + 规范文档 + 校验脚本** | **高** | 本规范要求 |

AI 只认最后一种。它读不到的颜色，它就会自己编一个。

## Token 分层：基础值 → 语义值 → 组件值

分三层，上层只能引用下层，不能跳层、不能写死。

```
基础值 (primitive)    blue-600: #2563EB      纯数值，无语义
       ↓
语义值 (semantic)     color-bg-canvas: {blue-900}
                     color-text-primary: #F8FAFC
                     color-status-alarm: #EF4444
       ↓
组件值 (component)    card-bg: {color-bg-canvas}
                     chart-series-1: {blue-500}
```

**为什么要分层**：换主题或调色时只改基础值与语义映射，组件层与页面自动跟随。若不分层，改一个主色要点遍全项目。

### 写法自由度（三种都合法，校验脚本都支持）

| 写法 | 形状 | 适用 |
|---|---|---|
| 扁平命名 | `{"semantic": {"color-bg-canvas": {...}}}` | 单主题、机器生成友好 |
| 分组嵌套（DTCG 风格） | `{"semantic": {"color": {"bg": {"canvas": {"$value": ...}}}}}` | 层级清晰、与设计工具对齐 |
| 多主题 | `{"primitive": {...}, "themes": {"dark": {...}, "light": {...}}}` | 深/浅主题、白天/夜间模式 |

层名不必叫 `primitive/semantic/component`，`base/alias/config` 这类同义词也可。命名与层名偏离默认时，校验命令加 `--layers 基础层名,语义层名,组件层名`。

### 多主题的强制要求

选择多主题时，**每个主题必须能独立解析出完整的语义层与组件层**（或明确声明继承自哪个主题）。禁止只改一半：某主题缺状态色会导致该主题下状态显示为默认色，这属于隐蔽缺陷，交付前必须逐个主题跑一遍阶段 5 的截图矩阵。

校验脚本对多主题的处理：必需 token 按**全部主题的并集**判定；某主题未重复声明时给出提示而非报错（允许继承写法）。

### 必备 token 类别

| 类别 | 必须包含 |
|---|---|
| 颜色 | 背景（画布/容器/浮层）、文字（主/次/禁用）、边框、状态（正常/警告/危险/离线）、图表色板（有序 8-12 色） |
| 字号 | 至少 6 级：超大数字 / 大标题 / 标题 / 正文 / 辅助 / 极小标注 |
| 间距 | 4 或 8 的倍数刻度，如 4/8/12/16/24/32/48 |
| 圆角 | 明确的有限几档，禁止随意值 |
| 阴影 | 有限几档，大屏通常弱化或不用阴影 |
| 层级 | z-index 分层定义（背景/内容/浮层/提示/遮罩） |
| 动效 | 时长与缓动曲线（大屏动效宜克制） |

## 大屏字号缩放策略（最重要的一条）

这是决定后期返工量的单一最大变量。三种策略，**必须在阶段 1 选定并写入真源**：

### 策略 A：等比缩放（scale 整个画布）

用一个固定设计稿尺寸（如 1920×1080），整体按比例缩放。

- **优点**：视觉与设计稿 100% 一致，实现简单。
- **缺点**：非 16:9 屏幕会出现留黑边或裁切；超宽拼接屏难以处理；浏览器字体在极端缩放下可能模糊；不适合需要真实响应式的场景。
- **适用**：单一固定终端、纯展示、比例完全确定的场景。

**与铁律 2 的关系（最容易搞混的一条）**：scale 方案本来就允许按设计稿写固定 `px`——由外层统一缩放，这是它相对断点重排的优势。但这**不等于"可以随手写 px"**：

- px 值必须登记为 **token 刻度**（如 `--space-16: 16px`），代码引用 token；
- 页面里裸写 `font-size: 13px` 仍属硬编码，`validate_tokens.py --fail-on-hardcode` 会判失败；
- 所以"设计稿 px"与"token 刻度"不是对立的：把设计稿的刻度搬进 token，再由代码引用。

**必须一并处理的代价**（写进 MASTER 时逐条填）：

- **非 16:9 屏幕**：留黑边还是裁切、裁哪一侧，先定死。
- **超宽拼接屏（如 32:9）**：单靠 scale 会把内容压得极扁，通常需要转混合策略。
- **极端缩放下字体发虚**：提醒现场避免非整数浏览器缩放。
- **canvas 图表要补偿 DPR**：容器被 `transform: scale()` 缩放时，图表须按 `devicePixelRatio × scale` 提高渲染分辨率，否则大屏上线条发虚。这一项在图表封装层统一处理，不要每个图各写一遍。
- **字号下限不因 scale 豁免**：缩放后的实际字号仍须满足阶段 0 按观看距离定的最小字号。

### 策略 B：断点重排（responsive）

按断点切换布局结构，字号用 `clamp()` 或断点调整。

- **优点**：适配各种分辨率与比例，无留边。
- **缺点**：设计与实现成本高，需要为每个断点定义布局。
- **适用**：终端类型多样（既有大屏又有笔记本）、信息密度需随屏幕变化的场景。

### 策略 C：混合（推荐用于多终端交付）

外层容器等比缩放，内部关键区域在极端分辨率下走断点重排。

- **优点**：兼顾一致性与适应性。
- **缺点**：最复杂，需要明确"哪里缩放、哪里重排"的边界。
- **适用**：同时交付工厂电视与控制室大屏、且都要精细效果的项目。

**强制要求**：选定后，所有字号与间距必须通过 token 或统一函数获取。禁止页面里出现裸 `font-size: 13px` 这类写法。**scale 方案不豁免这一条**：允许按设计稿写固定 px，但该 px 必须登记为 token 刻度并由代码引用。

### 字号随分辨率变化的推荐做法

优先用 CSS 原生能力（`clamp()` + `rem`），避免逐元素 JS 计算；JS 缩放只用于整体 scale 这类 CSS 难以表达的场景，且必须做 rAF + resize 防抖：

- 根字号随视口变化：`html { font-size: clamp(14px, 0.9vw + 6px, 22px); }`
- 全部尺寸用 `rem` 派生自根字号。
- 仅在 CSS 无法满足时才用 JS 缩放，且需监听 `resize` 并做防抖。

## 图表规范

图表是看板风格断层的高发区。必须在真源里定死：

| 项目 | 必须定义 |
|---|---|
| 图表库 | **唯一选型**，禁止页面临时引入第二个库 |
| 色板顺序 | 系列 1..N 的固定颜色顺序，与状态色区分 |
| 坐标轴 | 轴线颜色、刻度颜色、字号、网格线显隐 |
| 图例 | 位置、字号、图标样式 |
| 提示框 | 背景、边框、字号、触发方式 |
| 数值格式 | 千分位、小数位、单位、大数缩写（万/亿） |
| 空数据 | 统一空状态样式 |
| 加载态 | 统一骨架或加载指示 |
| 错误态 | 统一错误提示样式 |
| 自适应 | 容器尺寸变化时的重绘策略 |

## 产出

```
design-system/
├── MASTER.md           全局权威规范（人读）
├── design-tokens.json  机读 token（AI 与构建读）
└── pages/
    └── <page>.md       页面级受限偏离（可选）
```

起点模板：`assets/templates/MASTER.md`（含缩放策略、图表规范、**目录结构登记**三节）与 `assets/templates/design-tokens.example.json`。

> **目录结构登记是 Gate 的一部分**：`check_gates.py --stage 3/4` 默认查找 `src/layouts`、`src/components`、`src/charts`。项目若采用其他约定（如 `app/views`、`lib/ui`），必须在 MASTER 的「目录结构」小节登记真实路径，且按类别写明用途；登记了骨架目录不等于图表封装目录也合格，两者分开判定。

**层级检索规则**：构建某页面时，先查 `pages/<page>.md`；存在则其规则**覆盖** MASTER；不存在则只用 MASTER。禁止在页面里绕过这两层直接定样式。

## Gate 检查

- [ ] design-tokens 覆盖全部必备类别
- [ ] token 通过 `scripts/validate_tokens.py` 校验（退出码为 0；写法偏离默认形状时已加 `--layers`）
- [ ] 源码硬编码通过 `validate_tokens.py --fail-on-hardcode` 校验（退出码为 0）
- [ ] 大屏缩放策略已选定并写入文档（scale 方案的边界条件与 DPR 补偿已写明）
- [ ] 图表规范已成文，含空/加载/错误态
- [ ] 页面级偏离均登记在 `pages/` 下并有理由
- [ ] 页面代码中无硬编码色值与魔法字号（由校验脚本抽查）
