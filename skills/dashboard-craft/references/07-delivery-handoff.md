# 阶段 7 —— 交付与存档

## 目的

让交付物可复现、可回滚、可交接，而不是"只有开发者本机能跑"。

## 交付包内容

| 类别 | 内容 |
|---|---|
| 源码 | 完整可构建的代码仓库 |
| 设计真源 | design-tokens、MASTER 规范、页面级偏离 |
| 验证证据 | 截图基线、矩阵结果、性能报告、a11y 报告 |
| 测试资产 | Playwright 脚本、测试配置（可复跑） |
| 部署说明 | 构建命令、部署步骤、环境变量 |
| 回滚说明 | 回滚步骤与已知版本 |
| 运行手册 | 常见问题、日志位置、重启方式 |

## 基线资产必须入库

截图基线与测试脚本必须随代码版本管理。否则下次开发无法判断"是否退化"。

## 版本记录

维护一份变更记录，记录每次交付的：

- 版本号与日期
- 变更内容
- 基线是否更新及原因
- 已知限制

## 交接检查

- [ ] 新环境按文档可从零构建成功
- [ ] 测试脚本在干净环境可复跑
- [ ] 基线可复现（相同结果）
- [ ] 回滚路径已验证
- [ ] 已知限制已书面说明

## 下一步项目的复用

将本次的以下资产沉淀为**项目模板**，供下个看板项目直接复用：

- 环境约束卡模板
- design-tokens 初始集
- Layout Shell 骨架
- 图表封装层
- Playwright 视口配置与视觉回归配置
- 组件清单

这样"每个新项目重新搭一遍"的问题就被消除。
